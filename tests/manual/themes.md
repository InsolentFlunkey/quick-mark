# Theme native verification

Run these checks in a packaged or development desktop build on each supported platform.

1. In the right-aligned main editor toolbar control, use the Theme selector to choose Dark, Light, and Midnight in turn. Verify the choice applies immediately and editor, preview, toolbar, tabs, dialogs, hover/pressed/focus/disabled states, warnings, errors, selections, and code blocks remain readable.
2. Open Settings after each toolbar change and verify its Theme value matches. Change the theme in Settings and verify the toolbar value updates without reopening the window.
3. With two editor windows plus README, Markdown Cheat Sheet, and Markdown Examples open, change the theme. Verify every open window updates and a newly detached window starts with the selected theme.
4. Close every QuickMark window, relaunch, and verify the last selected theme is restored.
5. Verify native title bars and menus use the requested light/dark appearance where the platform permits; record any platform-rendered limitation rather than treating it as a web-theme failure.
6. Print or open print preview from each screen theme. Verify the result remains black text on white paper with readable tables, links, blockquotes, inline code, and fenced code.
7. Navigate to both Theme selectors with the keyboard, change each value with arrow keys, and verify a visible focus indicator remains. At narrow window widths, verify the wrapping toolbar does not obscure document actions, View controls, status text, or either Theme selector.
